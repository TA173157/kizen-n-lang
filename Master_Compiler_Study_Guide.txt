================================================================
1) Full Pipeline Overview
================================================================
Source code goes through these stages:

1. Lexer
   - Input: raw source text
   - Output: token stream

2. Parser
   - Input: token stream
   - Output: AST (Abstract Syntax Tree)

3. Semantic Analyzer
   - Input: AST
   - Output: validated AST (or semantic error)

4. IR Generator
   - Input: valid AST
   - Output: LLVM IR module

Simple memory model:
Text -> Tokens -> Tree -> Meaning checks -> IR instructions

================================================================
2) Visual Flow (Stage-by-Stage)
================================================================

Lexer flow:
  skip spaces -> read char -> classify -> build token -> repeat -> EOF

Parser flow:
  parse_program -> parse_statement repeatedly -> parse_expression by precedence -> AST root

Semantic flow:
  enter global scope -> visit AST nodes -> type/scope/rule checks -> success/error

IR flow:
  initialize LLVM objects -> visit nodes -> emit instructions/basic blocks -> final module

3) Language Building Blocks
================================================================
The architecture uses:
- `TokenType` enum for lexical categories.
- `Token` for typed lexeme.
- `Type` for semantic type model (including pointer/array/class nesting).
- AST node hierarchy (`Expr`, `Stmt`, `ProgramNode`).
- Visitor pattern to run multiple passes on same AST:
  - semantic checking pass
  - LLVM IR generation pass

================================================================
4) Token.h (What each part does)
================================================================
Main purpose:
- Defines token categories, token object shape, and semantic type representation.

Key parts:
1. `TokenType`
   - operators, keywords, literals, punctuation, EOF, IO tokens.

2. `Token`
   - `type`: token category
   - `value`: lexeme text (`string_view`)

3. `Type`
   - `base`: base kind (`INT`, `FLOAT`, `CLASS`, etc.)
   - `innerType`: nested type for pointer/array
   - `structName`: blueprint/class name
   - `arraySize`: array length metadata
   - overloaded equality to compare complex nested types recursively

Why this file matters:
- Parser uses `TokenType` to decide grammar.
- Semantic analyzer uses `Type` equality for correctness checks.

5) Lexer.h + Lexer.cpp (Function-wise understanding)
================================================================

Class state:
- `src`: source code text
- `pos`: cursor index
- `keywords`: maps reserved words to token types

Functions:

1. `Lexer::Lexer(string_view)`
   - initializes source and keyword table.
   - converts strings like `if`, `let`, `function` into keyword tokens.

2. `peek()`
   - returns current char without moving.

3. `peekNext()`
   - one-char lookahead for compound tokens.

4. `advance()`
   - consumes current char and moves forward.

5. `getNextToken()`
   - core tokenization engine.
   - skips spaces.
   - detects token category using a state machine:
     - state 0: token start / operator branches
     - state 1: identifiers/keywords
     - state 2: numeric literals
     - state 3: string literals
     - state 4: char literals

Important operator handling:
- supports: `==`, `!=`, `<=`, `>=`, `<<`, `>>`, `+=`, `-=`, `/=`, `*=`, `&&`, `||`, `->`, etc.

Notes:
- returns `ERROR` token for unknown chars or unterminated literals.
- `++/--` lexer handling appears partially commented in current code.

6) AST.h (Node model and Visitor system)
================================================================
Purpose:
- Defines all syntax tree node classes.
- Defines abstract visitor interface to process those nodes.

Core classes:
- `Node` (base)
- `Expr` (expression base, with `isAssignable`)
- `Stmt` (statement base)

Expression node set:
- `LiteralExpr`, `VariableExpr`, `BinaryExpr`, `UnaryExpr`, `AssignExpr`
- `MemberExpr`, `ArrayAccessExpr`, `CallExpr`, `DereferenceExpr`, `InstantiateExpr`

Statement node set:
- `VarDeclStmt`, `ExprStmt`, `BlockStmt`
- `IfStmt`, `WhileStmt`, `ForStmt`
- `ReturnStmt`, `BreakStmt`, `ContinueStmt`
- `FunctionStmt`, `BluePrintExpr`, `PrintStmt`, `ScanStmt`
- `ProgramNode` as root

Why visitor matters:
- Same AST can be reused by semantic and IR passes without changing AST classes.

================================================================
7) parser.h + parser.cpp (Token -> AST)
================================================================

Parser helpers:
- `peek()`: current token without consuming
- `consume()`: consume token and move
- `consume_if(type, msg)`: enforce expected token
- `throw_error(msg)`: parse error throwing
- `is_at_end()`: EOF check

Type parser:
- `parse_type()`
  - parses primitive or class name type
  - then wraps with pointer (`*`) and/or array (`[]`) repeatedly

Program parser:
- `parse_program()`
  - loops until EOF, collecting statements

Statement parsing dispatcher:
- `parse_statement()` routes to:
  - return/break/continue
  - if/while/for
  - block
  - variable declaration
  - function declaration
  - blueprint declaration
  - print/scan
  - expression statement fallback

Expression parser:
- `parse_expression(min_bp)` is Pratt parser:
  1) parse prefix atom/operator
  2) loop postfix/infix operators by binding power
  3) build AST respecting precedence + associativity

Binding-power table:
- `get_binding_power(op)` controls precedence for assignment, logical ops,
  comparisons, shifts, arithmetic, unary forms, etc.

8) SemanticAnalyzer.h + SemanticAnalyzer.cpp
================================================================

Purpose:
- Verify AST is meaningful and type-correct.

Core state:
- `scopes`: stack of symbol maps (nested scopes)
- `current_type`: inferred type from latest expression visit
- `current_function_return_type`: return context tracker
- `loop_depth`: to validate break/continue usage

Key support functions:

1. `enter_scope()` / `exit_scope()`
   - push/pop symbol table layers.

2. `declare(name, type, isFunc, fType)`
   - inserts symbol into current scope.
   - prevents duplicate declaration in same scope.

3. `lookup(name)`
   - searches innermost to outermost scope.

4. `throw_error(msg)`
   - throws semantic error with standard prefix.

Main entry:
- `analyze(ProgramNode*)` -> starts visitor traversal.

Major visitor checks:

- `visit(LiteralExpr*)`
  - sets `current_type` from literal token category.

- `visit(VariableExpr*)`
  - ensures variable exists and sets type.

- `visit(BinaryExpr*)`
  - checks operand type compatibility.
  - enforces numeric rules for arithmetic.
  - returns boolean for comparisons/logical results.

- `visit(VarDeclStmt*)`
  - initializer type must equal declared type.
  - then declaration inserted.

- `visit(If/While/For)`
  - condition must be boolean.
  - loop depth managed for loop statements.

- `visit(BreakStmt*)` / `visit(ContinueStmt*)`
  - only valid when `loop_depth > 0`.

- `visit(FunctionStmt*)`
  - stores function signature.
  - enters function scope and declares parameters.
  - analyzes body.

- `visit(CallExpr*)`
  - callee must be function.
  - arg count/type must match.
  - expression type set to function return type.

- `visit(MemberExpr*)`
  - base must be class/blueprint type.
  - requested field must exist.

- `visit(ArrayAccessExpr*)`
  - index must be int.
  - base must be array.
  - output type becomes array element type.

- `visit(InstantiateExpr*)`
  - blueprint must exist.
  - result type is that class type.

9) IRGenerator.h + IRGenerator.cpp
================================================================

Purpose:
- Convert AST into LLVM IR instructions and control flow.

Main LLVM objects:
- `LLVMContext`
- `Module`
- `IRBuilder`

Generator symbol state:
- `NamedValues`: variable name -> stack allocation
- `StructTypes`: blueprint name -> LLVM struct type
- `StructFields`: blueprint field name -> index
- `currentVal`: current expression result value
- loop block stacks for break/continue

Important functions:

1. `IRGenerator::IRGenerator()`
   - initializes LLVM objects
   - declares `printf` and `scanf`

2. `getLLVMType(TokenType)`
   - language type -> LLVM type conversion.

3. `generate(Node*)`
   - entry for node codegen.

Expression visitor behavior:
- Literal: creates constants.
- Variable: loads value from alloca.
- Binary: emits arithmetic/comparison/logical instructions.
- Assign: resolves target pointer and stores value.
- Unary: emits neg/not; ++/-- partial.
- Member: uses GEP + load for struct field access.
- Call: emits function calls.
- Instantiate: allocates struct instance.
- Dereference/ArrayAccess: currently incomplete in this code.

Statement visitor behavior:
- VarDecl: alloca + optional initializer store.
- If: then/else/merge basic blocks.
- While: cond/body/end loop CFG.
- For: init/cond/body/inc/exit loop CFG.
- Return: return instruction.
- Break/Continue: branch to loop target blocks.
- Function: define function, allocate args, emit body, verify function.
- BluePrintExpr: create LLVM struct type + field index map.
- Print/Scan: emit C-library IO calls (`printf`/`scanf`).

10) End-to-End Traces
================================================================

Trace A: `let x:int = 5 + 3;`
1) Lexer -> LET, VAL(x), :, INT, =, INT_LIT(5), +, INT_LIT(3), ;
2) Parser -> VarDeclStmt(name=x, type=int, init=BinaryExpr(5+3))
3) Semantic -> checks int + int = int; matches declaration
4) IR -> alloca x; const 5; const 3; add; store into x

Trace B: `if (a < b) print(a); else print(b);`
1) Parser -> IfStmt with condition and two branches
2) Semantic -> condition must be boolean
3) IR -> compare + conditional branch + merge block

Trace C: function declaration
`function add(let a:int, let b:int): int { return a + b; }`
1) Parser -> FunctionStmt + Return(BinaryExpr(a+b))
2) Semantic -> declares function/params and validates return expr type
3) IR -> creates function signature and body with return instruction

================================================================
12) Common Failure Points and Meaning
================================================================
If lexer fails:
- likely unsupported char/operator or unterminated literal.

If parser fails:
- grammar mismatch, missing token (`)`, `;`, `}`), or precedence issue.

If semantic fails:
- undefined symbol, type mismatch, bad function call args,
  or illegal break/continue placement.

If IR fails/crashes:
- missing AST visit implementation, wrong type mapping,
  unresolved struct metadata, or null current value.

13) Important Current Gaps (based on your current code)
================================================================
1. Increment/decrement handling is not fully integrated end-to-end.
2. IR float/double mapping appears simplified in `getLLVMType`.
3. Struct handling contains hardcoded `"Player"` assumptions in some paths.
4. IR visitors for dereference/array access are currently incomplete.
5. Minor naming typos (`feild`, `NILL`) reduce readability (not fatal).

16) Feature-by-Feature Checklist
================================================================
Whenever adding a new language feature:
1) Tokenization added?
2) Parsing rule added?
3) AST node support added?
4) Semantic validation added?
5) IR emission added?
6) Example program tested?
